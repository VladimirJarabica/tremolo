## Project Overview

Tremolo is a web application for creating and managing music sheets using ABC notation (https://abcnotation.com/). Users authenticate via Supabase and own their sheets and lists. ABC content is rendered and played back client-side with `abcjs`.

### Core Data Entities (`be/db/schema.prisma`)
- **Sheet**: `id`, `slug` (unique), `title`, `author?`, `source?`, `content` (ABC), `meter`, `tempo`, `scale`, `userId`, `deletedAt?` (soft-delete), `tags` (many-to-many via `_SheetToTag`), `listItems`.
- **Tag**: `id`, `name` (unique, **global** — shared across users, so names collide).
- **List**: `id`, `name`, `sheetIdsOrder` (`String[]`, denormalized ordering), `userId`, `items`.
- **ListItem**: `transpose`, composite PK `@@id([listId, sheetId])` — the source of truth for list membership.
- **User**: `id`, `email` (unique), `authId?` (Supabase, unique), `deletedAt?`.

## Tech Stack

- **Framework**: Next.js 16 (App Router). Note: Next.js 16 renamed `middleware.ts` → **`proxy.ts`** (root `proxy.ts` is this project's middleware).
- **React**: 19.x
- **Styling**: Tailwind CSS 4
- **Language**: TypeScript (strict mode enabled)
- **Auth**: Supabase (`@supabase/ssr`) — see `lib/supabase/`
- **Database**: PostgreSQL with Prisma 7 (schema/migrations) + Kysely (query builder, types generated by `prisma-kysely`)
- **Cache**: Redis via `ioredis` (`be/db/cache.ts`), serialized with `superjson`
- **Rendering/playback**: `abcjs` (sheet music), `@dnd-kit/*` (drag-and-drop), `fuse.js` (client search)
- **Client state**: `@tanstack/react-query`, `@tanstack/react-pacer`
- **Validation**: Zod
- **Testing**: Vitest
- **Linting**: ESLint with `eslint-config-next`

## Architecture

```
FE Component → Server Action → BE Function → ApiResponse<T>
                    ↑               ↑
              handleGuardedApi   Auth Guards (be/auth/guards.ts)
                                Zod validation
                                DB (Kysely) / Cache (Redis)
```

- **BE functions** (`be/*/`): Contain business logic, Zod validation, DB operations.
- **Server actions** (`app/actions/`): Thin wrappers with `"use server"`, wrap BE in `handleGuardedApi`, `revalidatePath` on success.
- **All operations return `ApiResponse<T>`**: `{ success: true, data } | { success: false, error: { code, details? } }`.
- **Auth flow**: `lib/supabase/server.ts` → `be/auth/get-user.ts` (`getCurrentUser`) links/creates the `User` row from the Supabase identity.

## Auth & Access Control

**Every BE function — including reads — must enforce authorization.** Guards live in `be/auth/guards.ts`:

- `getUserContext()` — any authenticated user (throws `AuthError` otherwise).
- `requireUser(id)` — the specific user.
- `requireSheetOwnership(sheetId)` — loads the sheet and verifies `userId` matches.

**⚠️ Important:** Sheets have a `userId` owner but **no `isPublic`/visibility field**. There is currently no `requireListOwnership` helper. Before adding reads or new entities, scope queries by `userId` (or an explicit visibility flag) and key any Redis cache entries by user. See `docs/CODE_REVIEW.md` for the access-control gaps identified in the latest review.

## Database Conventions

- UUID primary keys via `gen_random_uuid()`.
- All models have `createdAt` and `updatedAt` timestamps. **Updates must set `updatedAt: new Date()` manually** in `.set()` — the DB does not auto-update it.
- Soft-delete via `deletedAt DateTime?` on `Sheet` and `User`; filter reads with `.where("deletedAt","is",null)`.
- Many-to-many relations use Prisma implicit join tables (e.g. `_SheetToTag`).
- `ListItem` uses a composite PK `@@id([listId, sheetId])`; ordering is additionally stored denormalized in `List.sheetIdsOrder`.
- **Foreign-key columns are not auto-indexed** — add `@@index([userId])` (and on `listId`/`sheetId`) when adding relations that are queried/joined.
